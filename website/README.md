# relayapp.sh

Relay's website: the landing page and [/releases](https://relayapp.sh/releases).
Static files, built by one script and served by Cloudflare Pages (project
`relayapp`).

```sh
npm install
npm run dev       # build, serve on http://localhost:4321, rebuild on change
npm run build     # build into dist/
npm run preview   # build, then serve dist/ the way Pages does (wrangler pages dev)
npm run deploy    # build and deploy from this machine (needs `npx wrangler login`)
```

## How it's put together

- `build.mjs` — the whole build: bundles `src/js` and `src/css` with esbuild
  (content-hashed names), expands the HTML templates in `src/`
  (`{{value}}`, `{{{raw}}}`, `<!-- @include name -->` for `src/partials`),
  and copies `public/`. No framework.
- **Releases come from GitHub.** The build fetches the repository's releases
  and writes `/releases` from them: each one's changes, DMG, size and
  SHA-256. The same data fills in every download button and these
  redirects: `/download` (the newest stable DMG), `/download/rc` (the newest
  release candidate), `/github`, `/issues`. In CI the build fails if GitHub
  can't be reached; locally it falls back to the last fetch
  (`.cache/github.json`, or `node build.mjs --offline`).
- **The app in the page is HTML.** `src/js/mocks.js` redraws the Mac window,
  the iPad and the iPhone from the SwiftUI views (every size in em, so a
  mockup scales like a picture). The build renders their first frame into
  the page; in the browser, `world.js` holds a mockup's state (sessions,
  selection, which connections are warm), `term.js` is the pretend terminal,
  and `scripts.js` / `demos.js` are what runs in them. `data.js` is the
  made-up workspace they show.
- `src/js/field.js` — the background: a grid of terminal cells that the
  pointer stirs, on two canvases (the resting grid is drawn once).
- Everything animated stops when it's off screen or the tab is hidden, and
  holds a still frame under `prefers-reduced-motion`.

When the app's UI changes, the mockups to update are in `src/js/mocks.js`
and `src/css/mock.css`; the copy is in `src/index.html`.

## Deploying

[`.github/workflows/website.yml`](../.github/workflows/website.yml) builds
and deploys on every push to `main` that touches `website/`, after each run
of the Release workflow, and when a release is edited by hand — so a new
release shows up on the site without anyone touching it. It needs two
repository secrets:

- `CLOUDFLARE_ACCOUNT_ID`
- `CLOUDFLARE_API_TOKEN` — a token with the account permission
  **Cloudflare Pages: Edit** (My Profile ▸ API Tokens ▸ Create Token ▸
  Custom token).

The domain is attached to the Pages project in the Cloudflare dashboard
(Workers & Pages ▸ relayapp ▸ Custom domains). `public/_headers` sets the
security headers and caching; `_redirects` is generated by the build.

## Fonts

JetBrains Mono (the terminal's, subset to what the pages print) and Inter
(only fetched where there's no San Francisco), both under the SIL Open Font
License — see `src/assets/fonts/`.
